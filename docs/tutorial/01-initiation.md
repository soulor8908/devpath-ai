## 1.1 问题陈述：自学开发者转 AI 的痛点

2026 年，前端工程师想转 AI 方向，会遇到什么？

**痛点 1：通用工具找不到方向。**

打开 ChatGPT 问"前端怎么转 AI"，它会给你一个泛泛的学习路线图，但：
- 不知道你已有的技能（TypeScript / 异步 / HTTP / 组件化思维都是可迁移资产）
- 不知道哪些是高频考点、哪些是边缘知识
- 内容无出处，无法验证可信度

**痛点 2：AI 生成内容没权威、无出处。**

让 LLM 现场拆知识树、生面试题，质量不可验证、内容无出处、错误无追责。职业提升场景下，用户需要的是官方文档、论文、经典实现这些**有出处（provenance）**的内容。LLM 应该是导师，不应该是教材本身。

**痛点 3：学了就忘、不知道会不会。**

现有体系验证的是"你记住了吗"（选择题 / 面试题），而不是"你能造出来吗"。技能习得的第一性原理是：**Skills are built by doing, not by reading.** 没有项目、没有代码执行验证、没有作品集产出，学习就没有终点证据。

**痛点 4：坚持不下去、状态起伏。**

学习计划永远赶不上变化：今天加班没空、明天心情不好、后天生病。靠意志力坚持的学习产品，留存率不到 10%。需要的是：
- 告诉你"现在该做什么"的节奏引擎
- 预测你明天容量的能量模型
- 识别多巴胺干扰的情绪觉察
- 让进度外显为证据的成就系统

## 1.2 目标用户画像

### 主要用户：前端工程师 → AI 全栈 / AI Agent 工程师

```
姓名：小张（虚构典型用户）
背景：3 年前端经验，TypeScript 熟练，React/Vue 都用过
目标：转 AI 方向，3-6 个月内能独立交付 AI 产品
痛点：
  - 不知道该学什么（路径混乱）
  - 学了就忘（没有复习机制）
  - 不知道学会了没（没有验证闭环）
  - 坚持不下去（没有节奏引擎）
  - 没有证据证明自己（没有作品集）
```

### 次要用户

- **想转 AI 但不知从何下手**：用策展轨道避免「学了忘、忘了学」的低效循环
- **有基础但缺项目证据**：通过 V3 项目审查 + V4 作品集把零散学习变成可证明的能力
- **自学能力强但需要节奏**：番茄钟 + 节奏引擎 + FSRS 复习帮你坚持而不靠意志力

### 不该用 devpath-ai 的用户

- 想找「3 天速成 LLM」的（这里没有捷径）
- 想让 AI 直接生成面试答案的（违反内容生成宪章，会被守护测试拦截）
- 不愿意写代码只想看视频的（V2 代码沙箱是必经环节）
- 想要纯理论 / 学术研究的（devpath-ai 聚焦工程交付，不教训练模型）

**乔布斯视角**：明确说"不该用"，是聚焦的体现。一个想为所有人服务的产品，最终谁都不满意。

## 1.3 三个核心矛盾

devpath-ai 的产品定位建立在三个核心矛盾上，每个矛盾对应一个架构层的解法：

| 矛盾 | devpath-ai 的解法 | 对应架构层 |
|---|---|---|
| 通用工具找不到方向 | 6 条预置策展轨道 + 跳过已掌握节点的最短路径 | L1 内容层 + L2 路径引擎 |
| AI 生成内容没权威、无出处 | Content-as-Code，每节点 ≥2 条 T0-T2 级权威来源 | L1 内容层 |
| 学了就忘、不知道会不会 | V1 FSRS 卡片 → V2 代码沙箱 → V3 项目审查 → V4 作品集 | L3 验证层 |
| 坚持不下去、状态起伏 | 番茄钟 + 节奏引擎 + 能量回归 + 情绪觉察 + 成就 | L4 交付层 |

**术语解释**：
- **Content-as-Code**：把知识库当作代码管理，用 YAML 文件存储 + Git 版本化 + CI 校验，不是数据库行
- **T0-T2 权威来源**：T0 = 官方文档/论文（一手规范）；T1 = 经典源码/Cookbook（一手实现）；T2 = 一线从业者深度文章（权威工程实践）；T3 = 二手解读（仅作补充）
- **FSRS**：Free Spaced Repetition Scheduler，基于遗忘曲线的科学复习调度算法
- **L1-L4**：项目的四层架构，详见 [第 3 章 产品设计](file:///workspace/docs/tutorial/03-product-design.md)

## 1.4 立项初心

### 1.4.1 一句话定位

**devpath-ai 是把自学者变成能独立交付 AI 产品的工程师的转型系统。**

不是学习工具，是身份转变。学习只是过程，能交付才是结果。

### 1.4.2 设计哲学（乔布斯视角的 6 条原则）

引用自 [docs/PRODUCT.md](file:///workspace/docs/PRODUCT.md) 第 "设计哲学" 章节：

1. **聚焦**：不做「想学什么都行」的通用工具，先做穿一条前端→AI 旗舰路径。一条被验证的 16 周转型路径，比一百条 AI 现场生成的路径值钱。
2. **说人话**：UI 文案是「我答对了」「现在该做什么」「休息 5 分钟」，不是「Confirm Mastery」「Next Action」「Break Session」。
3. **少即是多**：番茄钟 widget 只有 ring/card 两态；首页只有 6 区；底部导航只有 4 项。每多一个选项都是认知负担。
4. **真实场景驱动**：Demo 数据是真实前端工程师计划，不是 placeholder。每个功能都对应一个真实使用场景，没有「万一有人想用」的边缘功能。
5. **质量优先于功能数量**：986+ 测试 + 三层质量护栏（预防 / 检测 / 审计）+ 16 个守护测试。功能可以少，质量不能塌。
6. **用户拥有数据**：本地优先 + 可选同步 + 一键清除 Demo + 登出所有设备。数据归用户，不归平台。

### 1.4.3 第一性原理（卡帕西视角）

引用自 [devpath-ai-redesign.md](file:///workspace/devpath-ai-redesign.md) 第二部分，6 条原理：

1. **技能通过构建获得，不通过阅读获得**：神经层面，"看懂"和"会做"是两套回路。学习的最小单元是项目，不是文章。
2. **学习效率 = 路径优化问题**：给定目标技能图 G 和当前技能集合 S₀，最优路径是 G 的拓扑排序中跳过 S₀ 已覆盖节点的最短路径。
3. **遗忘是默认值，间隔重复是唯一的对抗手段**：艾宾浩斯曲线是生理事实。没有间隔重复机制的学习产品，用户两周后保留率不到 30%。
4. **反馈回路必须快且客观**：代码要么跑通要么报错，测试要么过要么不过——这是编程学习区别于其他学科的最大优势。
5. **权威 = 策展，不是生成**：2026 年 LLM 生成的二手内容无限供应且持续贬值，有出处的一手内容反而升值。
6. **动力 = 朝向一个身份的可见进展**：人坚持不下去不是因为懒，是因为看不到自己在接近"成为某种人"。

**6 条原理 → 4 个产品推论**：

| 原理 | 产品推论 |
|---|---|
| 1 (Doing) | 项目制课程，不是文章库 |
| 2 (Path) | 技能图谱 + 个性化路径引擎 |
| 3+4 (Retention+Feedback) | 保留现有 FSRS，新增可执行验证层 |
| 5 (Authority) | 策展式知识库，全链路出处追踪 |
| 6 (Identity) | 作品集即产出，学习即积累求职资产 |

## 1.5 与竞品的差异

| 维度 | devpath-ai | 普通学习网站 | AI 聊天工具 | 刷题平台 |
|---|---|---|---|---|
| 内容来源 | 仓库 YAML 策展 + T0-T2 权威来源 | UGC / 编辑整理 | LLM 即兴生成 | 题库 |
| 路径个性化 | 技能图谱 + 拓扑排序 + 跳过已掌握 | 固定课程 | 无 | 无 |
| 验证闭环 | V1 FSRS → V2 沙箱 → V3 项目审 → V4 作品集 | 选择题 / 测验 | 无 | 算法题 |
| 坚持机制 | 番茄 + 节奏引擎 + 能量回归 + 情绪 + 成就 | Streak | 无 | Streak |
| AI 角色 | 编排器（Persona + 画像 + 工具调用） | 无 / 辅助 | 主功能 | 无 |
| 输出证据 | GitHub 仓库 + 作品集 + 公开主页 | 证书 | 无 | 通过率 |
| 数据归属 | 本地 IndexedDB + 可选 KV 同步 | 平台服务器 | 平台服务器 | 平台服务器 |

**乔布斯视角的差异点**：
- **内容是护城河**：不是 LLM 现场生成，是策展式 YAML 知识库
- **验证是闭环**：不只是"记住了"，是"能造出来"（V2 沙箱 + V3 项目审 + V4 作品集）
- **数据归用户**：本地优先 + 可选同步，平台不持有用户数据

## 1.6 一个真实的立项反思

引用自 [devpath-ai-redesign.md](file:///workspace/devpath-ai-redesign.md) 第一部分的诊断：

> **现在的 devpath-ai 是一个寻找内容的学习引擎。重构的方向：把它变成一个有引擎的课程体系。**

这句话揭示了项目立项过程中的一个关键反思：

**初版的问题**：
- 知识库只有 151 条知识条目（约等于一个主题该有的深度）
- 知识树、面试题、学习计划全部由 AI 实时生成
- 没有人工编排，没有出处，没有质量控制
- 目标用户是"想学任何东西的开发者"——等于没有目标用户

**用第一性原理拆，问题有四个**：
1. 通用 = 无定位（工具定位，不是产品定位）
2. AI 生成内容没有权威层
3. 没有能力验证闭环
4. 机制过剩，内容贫血（给自行车装飞机引擎）

**重构方向**：
- 从"想学什么都行"收窄到"前端转 AI 旗舰路径"
- 从"AI 实时生成"改为"策展式 YAML 知识库 + AI 当导师"
- 从"记住就好"升级到"V1-V4 验证闭环"
- 从"机制过剩"转为"内容是护城河"

这个反思过程本身就是一节珍贵的课：**产品不是功能堆砌，是聚焦 + 第一性原理 + 真实场景驱动**。详细的迭代史见 [第 7 章 迭代更新](file:///workspace/docs/tutorial/07-iteration.md)。

## 本章小结

**学到了什么**：
1. devpath-ai 解决自学开发者转 AI 的 4 个痛点：方向 / 权威 / 验证 / 坚持
2. 目标用户是前端工程师 → AI 工程师，明确说"不该用"是聚焦的体现
3. 三个核心矛盾 → 四层架构（L1 内容 / L2 路径 / L3 验证 / L4 交付）
4. 设计哲学 6 条原则（乔布斯视角）+ 第一性原理 6 条（卡帕西视角）
5. 立项过程中的关键反思：从"寻找内容的学习引擎"到"有引擎的课程体系"

**关键决策回顾**：
1. 定位收窄：从"想学什么都行"到"前端转 AI 旗舰路径"（聚焦原则）
2. 内容策略：从"AI 实时生成"到"策展式 YAML + AI 当导师"（权威 = 策展）
3. 验证闭环：从"记住就好"到"V1-V4 四级验证"（Skills are built by doing）
